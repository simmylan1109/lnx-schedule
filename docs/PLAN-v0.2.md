## 二、课表(第 6 项,最大的一块)

### 2.1 数据模型:四张新表

用户选了"独立一套课表数据",所以课表里的课**不进日/周/月视图**,两边互不干扰。

```
terms            学期     id, name, startDate(第1周周一), weekCount, createdAt/updatedAt/isDeleted
periods          节次定义  id, termId, index(第几节), startMinute, endMinute
courses          课程     id, termId, name, teacher, location, colorSlot, createdAt/updatedAt/isDeleted
course_sessions  排课     id, courseId, dayOfWeek, periodId,
                         weekFrom, weekTo(第几周到第几周), createdAt/updatedAt/isDeleted
```

一条 `course_sessions` = "**高等数学**，周��第 1–16 周，**周三**第 3–4 节，**教三 401**"。
格子里显示什么,靠 `courses` 里的字段 + 时间靠 `periods` 拼出来。

**为什么不叫 `enrollment`** :英文 enrollment 在大学语境里常指"注册了这门课的人",
这里存的是"这门课每周什么时候上",叫 `course_sessions` 更准。

**和现有表一致的地方**(照抄 `EventEntity` 的规矩):主键 `String` UUID、单列索引、
**不建外键**(整个项目一个外键都没有,靠约定)、布尔存 INTEGER、**枚举存名字不存序号**。

### 2.2 入口怎么接进去

现在日/周/月是 `ViewMode` 枚举(`CalendarViewModel.kt:42`)驱动的三个顶部标签,
**底下没有任何导航库** —— 没有 Navigation Compose,也没有底部导航栏。

课表按用户选的"顶部标签加一个"接进去:

```kotlin
enum class ViewMode { DAY, WEEK, MONTH, TIMETABLE }   // 加一个常量
```

`ViewModeTabs` 是 `ViewMode.entries.forEach` 驱动的,所以加常量 + 一句 `stringResource`
+ `when(state.viewMode)` 里加一个分支,三处改动。

**关键是翻页逻辑天然吻合**:日历的横向 pager 现在就是**按周翻**的(`dateToPage`/`pageToDate`),
课表也是一周一屏。所以顶部标题栏不用大改 —— 选到课表时把"Oct 1, Thu"换成
"第 3 周 · 10/13 – 10/19",翻页照旧。

⚠️ 但有个东西必须注意:`CalendarViewModel.uiState` 是 5 个 flow `combine` 出来的,
课表的数据源跟日历**完全无关**(不共享事件表),所以要么加第 6 个 flow,
要么课表页自己开一个 ViewModel。倾向前者 —— 少一个状态源少一处不同步。

### 2.3 学期和"现在是第几周"

新设置项,照抄 `week_start_monday` 的做法(DataStore、**所有 key 都是 snake_case 的字符串**,
值全是 String,解析时 `runCatching` 兜底 —— 这个项目吃过"强类型 key 遇到旧版本写的不同类型
直接 `ClassCastException` 把设置流搞挂"的亏)。

- `current_term_id` — 当前学期
- 学期本身的起止和周数在 `terms` 表里

"今天是第几周" = `ChronoUnit.WEEKS.between(term.startDate, 今天)` + 1。
注意学期起始日要**对齐到周一**,否则第 1 周只覆盖半周。

### 2.4 课表要不要提醒

**待你拍板**(见第五节)。如果要做,改动比看上去大:

`NextReminderCalculator` 是个纯函数,但它的输入输出都是**按事件形状**的:

```kotlin
data class ScheduledReminder(val eventId: String, val occurrenceStart: LocalDateTime,
                              val remindAt: LocalDateTime, val title: String, val location: String?)
```

课程要提醒,得给它加一个"来源"标记(不然点通知回来,`MainActivity.handleOpenRequest`
拿着 id 只会去事件表里找,找不到),然后 `ReminderPlanner` 里把课程和事件两路结果合并。
`ReminderScheduler` 本身不用改 —— 它只认 `ScheduledReminder`,不关心那是什么东西。

## 三、课表数据怎么进来:从文件导入,不做内置浏览器

### 3.0 2026-10-01 定的方案(替代原"订阅 .ics")

用户实际情况:官网导出只有 XLS/DOC/CSV/TEXT 且 **CSV 导出是坏的**;有个第三方
App(WakeUp 课程表)能"订阅",但那是**它自己的服务器登进教务系统抓的**,学校不提供
任何订阅网址。计划给**一个朋友**用,**同一个学校**。

据此定的方案:

1. **不做"lnx 内置浏览器登教务系统自动抓"**。那是要为每所学校写适配器、还要引 XLS
   解析库(+2~3 MB 包体)、还得赌 WebView 能接住教务系统的导出下载 —— 为两个人、
   一学期一次的活儿付这个代价不划算。而且教务系统导出是 XLS 为主,逃不掉解析库。
2. **解析通用格式**:`.ics`(国际标准)和 `.csv`(纯文本)。两者都零依赖、零联网,
   包体一点不涨,也不用电脑转换。`.ics` 是 v0.1 重复规则引擎的直接输入。
3. **`.xls` 第一版不做**,遇到时提示用户"请在电脑上另存为 CSV"。XLS 是老式二进制,
   正确解析要引 Apache POI(+2~3 MB)——现在的包体卖点是 1.7 MB,不值。
4. **让 lnx 能被"用 lnx 打开"调用**(注册 `text/calendar`、`.csv` 的 intent-filter)。
   这一条比解析器本身还关键:朋友的流程变成
   **导出文件 → 微信传到手机 → 点文件 → 选"用 lnx 打开" → 课表排好**,三下点完。

这样还有个副产品:.ics 是通用格式,**从哪导都行**(教务系统的任何工具、Google 日历、
WakeUp、别的日历软件导出),lnx 不绑定任何一家。

### 3.1 为什么"适配格式"比"适配学校"划算

教务系统的导出格式全天下就那么几种。写几个**格式级**解析器,任何学校都能用;
而 WakeUp 那套要写的是**学校级**适配器(几百套),学校改一次页面就全废。
两种做法的工作量差几十倍。

### 3.2 不联网、不加权限(与原"订阅"方案的关键差别)

文件导入是**纯本地**的:选文件、读内容、写库,一步都不出手机。所以
**`AndroidManifest.xml` 保持没有 `INTERNET` 权限**,README 里"零联网、不收集、
不上传"这个卖点也不用改。这是放弃订阅换来的,值得。

### 3.3 导入的东西可以改

导入进来的课就是普通的课表数据,跟手动录的**没有区别**:可以改时间、换老师、
删掉某一周、调颜色。不像订阅那样只能读不能写 —— 因为文件已经在手机上了,
源头那份爱怎么改怎么改,跟你无关。

## 四、团队协作(第 7 项,建议 v0.3.0)

### 4.1 为什么必须拆出去

协作不是一个功能,是**一次产品定位的改变**。现在 lnx 的全部卖点之一是
"零账号、零联网、数据全在你自己手机上"。做了协作之后:

- 需要服务器(要花钱,或者你得自己有一台永不关机的机器)
- 日程数据**离开手机**了 —— 这是隐私承诺的实质性变更
- 需要账号体系(你现在没有,用户第一次用就得注册)
- 需要定冲突规则:两个人同时改同一节课,听谁的?
- 需要定共享范围:哪些日历、哪些标签给谁看
- 需要定权限:只读还是可编辑

这五条**缺一条都不成立**。而且它们都是**产品决策**,不是写代码能替你定的。

### 4.2 现在就要做的"设计税"

只有一条,但很便宜:**新课表四张表全部带上 `id`(UUID)+ `createdAt`/`updatedAt` + `isDeleted`**。
这是 v0.1 已经在 4 张表上立的规矩,照抄即可。导入合并已经按 `updatedAt` 做冲突取舍,
这套机制将来能直接映射成同步协议。

## 六、已经查明的坑(不用你操心,但你该知道)

1. **备份格式版本必须从 1 升到 2**。加新课表数据而不升版本的后果是:
   用新版导出、老版导入 → **课表数据被静默丢弃,一句错都不报**。
   升了版本之后,老版本会明确报"这个备份来自更新的版本",这才是对的行为。
   (`BackupModels.kt:8-12` 写着这条规矩,别绕过它。)
2. **新增的备份 DTO 必须放在 `com.lnx.app.core.backup` 包下**。`proguard-rules.pro` 里那几条
   `-keep` 是按这个包路径写的,放别处 R8 会把序列化器优化掉,
   后果是"发布包里备份功能坏掉" —— 而这个在开发机上**永远看不出来**。
3. **加 DAO 之后,`TestDatabaseModule` 必须同步加 provider**,否则**所有**仪器测试都会挂。
4. 仪器测试方法名是中文但**不能含空格**(minSdk 26 的 DEX 拒绝),用下划线。
5. 新界面上每个可点的元素都要有 `testTag` 和朗读文案,否则 `AccessibilityGateTest` 直接转红。
6. 数据库 v3 → v4 是纯建表、不搬数据,按 `LnxMigrations.kt` 里那五步清单走,
   `MigrationChainTest` 会盯着(versionCode 不涨、迁移漏写,立刻红)。

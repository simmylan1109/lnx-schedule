S1 里定下来的三件事,后面都按这个来:

1. **服务端 Kotlin 是 2.2.0、App 是 2.0.21,故意不一样** —— App 锁版本是 Android 工具链
   的约束,服务端没这个约束,跟着 Ktor 要求走即可。协议 DTO 两边对齐靠约定,不靠同版本。
2. **同步游标用服务端自己的单调序号 `server_seq`,不用客户端的 `updatedAt`**。
   客户端时钟不可信(改时间、时区差、两人改同一条毫秒数撞车),拿它当游标一定会漏数据。
3. **同步单位是"行",主键 `(user_id, entity, entity_id)`**;`payload` 存整行 JSON、
   服务端不解释业务字段(以后 App 加字段不用改服务端),软删除墓碑也存成一行不真删。

S2 里再加两条:

5. **库里存令牌的 SHA-256 指纹,不是令牌本身** —— 数据库(含每日备份)泄露不等于令牌泄露。
   口令用 Argon2id,校验时读哈希串里自带的参数,所以以后调参不影响老用户。

## 二、技术选型(待用户过目)

| 层 | 选择 | 为什么 |
|---|---|---|
| 服务端语言 | **Kotlin + Ktor** | 与 App 同语言:同步协议的 JSON DTO 可以**两边共用一套定义**,协议漂移的风险从根上消掉 |
| 服务端数据库 | **SQLite(单文件)** | 2 GiB 内存的机器不值得再养一个数据库进程;单文件备份 = `cp` 一条命令 |
| 进程管理 | systemd | Ubuntu 原生,开机自启、崩溃自动拉起 |
| TLS | 服务器生成自签证书,App **证书固定**(pin) | 无域名 Let's Encrypt 走不通;自签 + pin 比关证书校验安全得多 |
| 密码存储 | argon2(服务端) | 行业现行标准,不许再出现任何"口令进文本"类事故 |
| 凭据传输 | HTTPS(自签),token 放内存 + 加密存储 | — |

## 三、数据与冲突模型

v0.1 SPEC §4.5 预留的三件套(**UUID 主键 / createdAt·updatedAt / 软删除**)就是为此:

- **同步单位 = 行**。每行带 `updatedAt`;两端同 id 冲突时 **新 updatedAt 赢**(与现有备份合并同一规则)
- **拉取**:客户端带着"上次同步点"调 `pull`,服务端把该点之后变过的行给回来
- **推送**:客户端把本地变过的行 POST 上去,服务端逐行 LWW,返回权威结果
- 首期共享范围:**整个日历**(2 人场景,不做"哪些给谁看"的粒度 —— 那是加人之后的事)
- **不做实时推送**(FCM 在国产 ROM 上不可靠):打开 App / 手动刷新时拉取,本地改动即时推送

6. **冲突判定:同一行的两个版本谁的 `updatedAt` 大谁赢,相等时服务端赢。**
   相等时必须让服务端赢 —— 让客户端决定会导致两端反复覆盖,用户看到同一条日程反复变内容。
   迟到的删除同样被拒,免得把别人刚改过的内容悄悄抹掉。
7. **推完之后游标不变**,客户端必须照旧再拉一次。推完就把游标推到"本次用掉的最大序号",
   会静默跳过两台手机并发时落在中间的行。

S4 里定下来的(部署脚本在 `D:\lnx-server\deploy\`,手册 `deploy/部署步骤.md`):

8. **nginx 终结 TLS,服务只监听 127.0.0.1**。Ktor 3.6 **把 Netty 的 TLS 支持整个删掉了**
   (`sslConnector` 与 `EngineSSLConnectorBuilder` 都没了),所以服务自己没法说 https。
   这样排反而更安全:服务从公网上根本够不着,令牌不可能走明文。
9. **自签证书里故意不写主机名**。证书会被打包进 APK 而 APK 发在 GitHub,证书里写着
   服务器地址就等于又泄露一次。App 侧用证书固定(只认这一张、完全不看主机名),
   比 CA 校验更严格。**App 侧实现时必须做到"不校验主机名"**,否则连不上。
10. **部署脚本只给用户执行,服务器凭据永不入库**。邀请码用隐藏输入读,
    写进 `/etc/lnx-server.env`(权限 600),不进命令行、不进 shell 历史。
    systemd unit 里**只写 `EnvironmentFile=` 路径,不写值** —— unit 文件是全局可读的。

## 五、风险与丑话

1. **这是 lnx 第一次联网**,README"零联网、不收集"的承诺要改写成"联网仅用于你配置的
   自己的同步服务器;不向任何第三方发送数据"。这句文案用户确认后才发。
2. **2 GiB 内存的机器**,同时跑系统和 JVM 服务绰绰有余,但别再指望它干别的重活。
3. **IP 换了,两台手机要改一次服务器地址**(App 内可改,一分钟)。用户已有心理预期。
4. **服务器是个长期责任**:到期续费、安全更新(`apt upgrade`)、SQLite 备份——我会把
   这些做成脚本和文档,但"记得续费"这件事只有用户自己能负责。
5. **账号找回没有邮件**:邀请码制 + 两台设备起步,口令忘了由服务器管理员(用户本人)
   在服务器上重置,不做自助找回。

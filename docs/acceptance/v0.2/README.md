## 补欠账 ①:引导页/设置页主题卡滑动提示

修复前的事实:4 张主题卡(4×112dp + 间距 + 边距 ≈ 524dp)在手机屏(约 392dp)上放不下,
**第 4 张「宁静冷色」完整地藏在屏幕右边缘之外,连一条边都不露** —— 用户不知道右边还有东西。
设置页与引导页共用同一个 `ThemeCardRow`,两处一起修。

![主题卡与圆点提示](01-theme-dots-hint.png)

两重提示(引导页与设置页同款):

1. **底部一排 4 个位置圆点**,滑到哪儿亮到哪儿;整行放得下时不画(平板不凭空多一行);
2. **引导页首次出现时自动"滑到底再弹回来"一次**(autoPeek),亲手演示比文字提示有效。
   演示有保险:用户已经自己滑过就不再动手,不然会把用户正在看的位置硬拽回去
   (这个边界是被测试逼出来的,见下)。

配套仪器测试 `OnboardingTest.第4张主题卡藏在屏幕外_有圆点提示_向左滑之后可达`:
断言圆点存在 + 向左滑之后第 4 张卡真的进语义树(LazyRow 不组装屏幕外的项,
"存在且有尺寸"本身就是"看得到"的证据)。

### 顺带拆掉的地雷:日期炸弹测试

全量仪器测试跑到 `BackupErrorClassificationTest.导出成功给文件名并把内容写出去` 报红,

## 补欠账 ③:仪器测试的文案定位改为资源现取

修复前的事实:十几处仪器测试按**写死的中文文案**定位界面(空状态、"未分类"、"新建事件"、
"请填写标题"、"永不结束"……),能跑全靠 `HiltTestRunner` 把进程语言钉死成中文 ——
钉钉子的那一行要是坏了,这些断言会**一起静默失效**。

- 8 个测试文件里的框架文案定位全部改为 `targetContext.getString(R.string.…)` 现取
  (月视图的日期格式改用生产同一套 `LnxLocale.monthDay`,拼法不再各抄一份)
- 三条 M3 时代的"占位文案不存在"死断言(断言一段早已不存在的文字不存在,恒真)删除
- 语言切换相关的两条测试(LocaleSwitchTest / LanguagePersistenceTest)**故意保留**中文断言
  —— 断言"切到英文后中文消失"正是它们的目的
- 测试自己 seed 的数据标题("工作"、"月列表事件"这类)不属于框架文案,不动

## 补欠账 ④:标准验收数据集固化

`demo-week-backup.json` —— 周视图"所有天都画在同一列"那个 bug 活了九个里程碑的根因是
验收数据恰好全是单日事件。这份文件把"多条 + 跨维度"的验收数据固化进仓库:

- **全部"每周重复、永不结束",锚在过去一周** —— 任何一周打开都有内容,数据集永不过期
- 一周 7 天全有日程;周三"需求评审"+"项目同步"同时段 → **车道并排**有活证据;
  周日全天事件 → 全天横条;两个标签(工作/生活)

配套 8 条 JVM 合同测试(`DemoWeekBackupTest`):格式合法、维度齐全、字段卫生,
并用**真的 RecurrenceEngine** 跑一遍验证任意一周每天都有发生 —— 数据集要是坏了或被
误改,单测当场红。

**人工走查用法**:走查前「设置 → 导入」选这个文件、选合并,然后翻周视图核对多列/并排/全天横条。

## 走查抓到的三个 bug(测试全绿时抓到的)

1. **设置页是透明的**(M6 就带着)。`SettingsScreen` 根节点只填尺寸不画底色,盖在日历上时
   日历整片透出来 —— 顶栏标题和 Day/Week/Month 叠在一起,滑到底连当前时刻的红线都看得见。
   **M6 的验收截图 `docs/acceptance/m6/05-settings-en.png` 里能直接看到,当时被当成合格证据收进去了。**
   修法:根节点换成 `Surface(color = background)`。编辑器没事,是因为它用了 `Scaffold`
   (自带 containerColor),搜索页没事,是因为它用了 `Surface`。

2. **导出的备份文件里没有 `format` 和 `version`**。编码器开了 `encodeDefaults = false` 省体积,
   而这两个字段恰好等于默认值,于是被一起丢掉了 —— 文件失去自我标识,任意形状相同的 json
   都能被当备份读进来。往返测试 `decode(encode(x)) == x` 照样通过,查不出来。
   修法:这两个字段加 `@EncodeDefault(ALWAYS)`,并补一条**直接断言文件里有没有这两个键**的测试。

3. **英文 "Contains 1 events"**。中文没有复数,英文有;事件数与标签数各自成词,
   一个 `string` 带两个 `%d` 没法分别选单复数。修法:拆成两个 `plurals` + 一个拼装句。

4. **主题 4 头部叠层**(T4 自己踩的):渐变容器是 Box 作用域,顶栏和 Tab 叠在同一层。

## 终审整改(4 个 P1 全修)

独立终审子代理给出 4 个 P1、11 个 P2。P1 全部修掉并补了回归测试,P2 修了 5 个便宜的
(对比度、注释撒谎、警告条数实时算、覆盖导入关联去重、导入计数口径),其余记录在案。

1. **备份格式闸门有洞**:kotlinx 会给缺省键填默认值,`{"events":[]}` 解出来 `format`
   恰好等于 `"lnx-backup"`,任意形状相同的 JSON 都能被当备份读进来,走覆盖就是清库。
   修法:解码前先查 `format`/`version` 两个键**显式存在**。
2. **同名不同 id 的标签合并被静默吞掉**:name 有唯一索引,`@Upsert` 撞索引后吞异常、
   按新 id UPDATE 影响 0 行 —— 标签消失但关联插进去了(幽灵关联)。
   修法:合并前按名字对齐,同名沿用库里那条 id,关联重映射。
3. **搜索跳转的高亮在"日视图已开"路径下必丢**:程序化翻页也会触发翻页回写,
   回写经 `selectDate` 把刚设上的高亮清了。修法:日期没变不回写 + 不清高亮。
4. **全天事件的搜索结果行丢了日期**,重复+全天还会渲染成「下次发生:全天」。
   修法:复用 `detail_all_day_single` 模板,全天也带日期。

补的测试:备份链路的**例外**(重复事件的命门)此前零真库用例,补 3 条;
同名标签合并 2 条。测试基线 232 单测 + 133 仪器,全绿。

## 红检验证

18 条搜索仪器测试首次全绿,可疑。做了红检:把 DAO 查询里的 `ESCAPE '\'` 去掉,
`百分号当普通字符搜` / `下划线当普通字符搜` 两条立刻转红,证明它们真在守 `LIKE` 通配符转义。

`format`/`version` 那条 bug 本身就是红检 —— 上面第 2 点里贴的就是没修之前的真实导出文件内容。

# lnx 隐私说明

生效日期：2026-10-05

这份文档写给用 lnx 的人看。它不是法律术语的堆砌，是一句一句说清楚：
**这个 App 拿你的数据去做了什么、去了哪里、谁能看见、你能做什么。**

App 首次启动时会完整展示下面第 1–5 节（那时一个网络请求都还没发出去），
两份文字保持一致。

---

## 1. 现在：默认完全不联网

lnx 的日历功能全部在这台设备上完成 —— 新建、编辑、提醒、搜索、导入导出，
不发送任何网络请求。之前没有申请联网权限，那是承诺的强制力，不是遗漏。

从 v0.3 起 App 声明了联网权限（系统安装时授予、不弹框），但**默认不联网**；
只有你自己开启同步之后才会真的联网。

## 2. 开启同步后会发生什么

只有你主动开启跨设备同步，日历数据才会离开这台设备。

| | |
|---|---|
| **传输内容** | 日程标题、起止时间、地点、备注、重复规则、标签 |
| **目的** | 让**你自己**的多台设备保持一致 |
| **方式** | TLS 加密传输，并校验服务器证书（证书固定） |
| **保存期限** | 服务器保留到你删除账号；每日备份保留 30 天 |

传输只发生在**你的设备 ↔ 你自己的服务器**之间。没有第三方，没有中转。

## 3. 我们不做的事

- 不收集你的日历用于分析
- 不接入第三方统计、广告或追踪 SDK
- 不向任何人出售、出租或共享你的数据
- 不在 App 里写死任何服务器地址 —— 服务器是你自己配置的

## 4. 你的权利

- 随时在设置里**关闭同步**，关闭后 App 回到完全不联网的状态
- 随时**登出**。登出会立即删除服务器上属于你的全部数据
- 随时**删除账号**（设置 → 共享 → 删除账号）

需要注意的一点：**卸载 App 不会自动删除服务器上的数据**，服务器上的数据是你自己的
责任范围。登出或删除账号才会清掉它。

## 5. 服务器归你

同步用的服务器由你自己购买、自己配置、自己承担费用。lnx 只是客户端，
**你自己部署的服务器上发生的一切由你自己负责**，包括服务器本身的安全性、
是否备份、以及是否被他人访问。

服务器证书由服务器生成，并内置在 App 里做证书固定：App 只认这一张证书，
且不校验主机名。这比常规的证书校验更严格 —— 别人即使拿到了另一个有效证书，
App 也会拒绝连接。

需要说明的一点：证书固定保护的是**传输过程**，不等于端到端加密。
服务器上的数据在服务器上是可读的（服务器是你自己的机器），所以请保护好它。

这份说明如有变更，会更新本文件并更新上面的生效日期。
**App 在首次安装时展示当时的版本**；已经在使用的版本不会被重新弹出，
所以任何时候想知道最新约定，以本文件为准。

## 给开发者

改动这份文档或 App 内披露文案时，注意三条：

1. **不许写「我们不收集任何数据」。** lnx 客观上确实处理日历数据，这句话是虚假陈述。
2. **不许写「去中心化」。** 那是个营销词，而且用户买的是一台中心化服务器。
3. **不许把证书固定说成端到端加密。** 它防的是传输过程中间人，不是服务器本身。

这三条是有出处的：主流产品（Apple 区分两档数据保护、Syncthing 强调"你自己选存哪儿"、
Nextcloud 声明"你自己部署的实例不在我们的政策覆盖范围内"）都是这么写的。
App 内披露（`values/strings.xml` 的 `privacy_*`）和本文件必须一致 ——
两处说法不同，就等于承诺不一致。

4. **披露页目前没有"版本号"机制**：改了文案，已经读过的用户不会重新看到。
   现在是个人项目（用户就是你自己），先记着这笔账。哪天要正式面向外部用户，
   合规上"重大变更须重新取得同意"就是靠加一个披露版本号实现的 ——
   版本不一致就重新弹一次。代码里现在没有这个东西，不要以为有。
